# 扣分制评分规则 / v0.2.0

量表3.0、策略1.0、审查结构2.0分别版本化。

每维度按100分起算，只扣已确认问题。默认轻微3、中等10、严重20、致命40；最低0。通过指标不加分，指标没有权重。所有分值从scoring-policy.json读取，不允许问题手填points或检查手填weight。

综合基础分为各维度分乘有效权重之和。一般情况下有效权重就是九维固定权重20/20/10/10/15/10/5/5/5%。只允许有明确基线依据的全维度NA剔除，并公开有效权重；部分指标NA不改变权重。

同一根因仅一条问题、一个主维度。问题可引用多个指标；同一指标可关联多个独立根因，分别扣分。维度内累计扣分可超过100，但实际扣分最多100；问题明细的单项总分影响明确标为封底前值，不与封底后的合计混淆。

已确认技术阻断须匹配策略里的阻断规则并有说明及证据，综合分封顶59。封顶单独展示，不计为新问题。严重度、关键验证和技术阻断分开；关键指标失败不自动升级为阻断。

所有适用原始指标检查完成，且基线已建立，才有正式总分与等级：≥80良好，≥60合格，<60不合格。尚有unknown时只显示已确认扣分下的暂评上限，不生成正式总分。完全未检查显示未评估。若已经确认阻断，可明确不满足上线条件，即使审查尚未完成。

完成度 = 已完成原始指标数 / 适用原始指标数。一个指标的子检查有任何unknown，原始指标就未完成。完成度不参与计分、不构成测试覆盖率或发现全部缺陷的概率。

每个fail须有关联confirmed问题及共同证据；pass也需要证据；NA和unknown必须有理由与基线引用。不得遗漏指标、隐藏关键未知或用假证据抬高分数。HTML和输入中的summary从不被信任，评分器重算并嵌入规则快照。
