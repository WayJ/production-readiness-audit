01 / GET STARTED

装上 Skill，一句话开始审查。

不需要 API Key、Node.js 或安装 Python 依赖。两步即可在任意项目里启动诊断。

01

安装 Skill

把完整 Skill 复制到宿主 Agent 支持的技能目录，不改宿主设置。

02

在新会话里调用

在要审查的项目目录新开会话，用下面任意一句提示词开始。

python scripts/install_skill.py --target ~/.claude/skills
在仓库根目录运行。安装器只复制白名单内的 Skill 文件，不会覆盖已有目录。不同宿主的技能目录不同，请按你的宿主文档替换 --target。

02 / A DEEPER REVIEW

不只是查“能不能运行”。

从业务结果一路追到实现与运行边界。每一个结论都有来源，每一分都有解释。

01 / REVIEW

真实漏洞与 Bug

追踪鉴权和危险调用，验证业务规则、异常状态与最终数据。扫描告警先复核，不把猜测写成缺陷。

查结果，不只看页面。
02 / REVIEW

架构、组织与并发

同一业务逻辑到处复制？状态只保存在单进程？并发请求能绕过额度校验？这些都有独立检查。

查具体影响，不偏爱某种框架。
03 / REVIEW

可执行的诊断报告

按维度查看得分和扣分，展开根因、影响、代码位置、证据与最小处理建议，直接交给下一步整改。

先诊断，不擅自修复。
03 / THE RUBRIC

九个维度，一套技术口径。

负责人、审批、签字和文档数量不计分。复杂架构不是加分项，实际能力才是。

04 / KNOW THE BOUNDARIES

诊断工具，不是自动上线按钮。

它不承诺发现所有漏洞，也不把高分当作发布许可。审查由具备项目访问能力的 Agent 或审查者完成；CLI 负责数据校验、计分和报告。

报告与官网没有远程统计、脚本或字体。真实报告默认排除出 Git；Pages 只使用虚构白名单样例。Agent 宿主的数据行为仍由宿主决定。

没有验证，会扣成不合格吗？

不会把未知说成已确认缺陷。未检查显示未评估；部分检查只显示暂评上限、待验证项数和完成度，不给正式分数。

代码复制就一定要扣分吗？

不是。要确认同一业务语义、多点维护或规则漂移的实际影响，也要避免为了复用而过度抽象。

支持 Windows 吗？

脚本使用 Python 标准库和跨平台路径，提供 py -3 命令及 Windows CI 配置。是否已在各平台实际验收，以仓库验收记录和 CI 结果为准。

能直接自动扫描项目吗？

当前版本不是自动扫描器。先由 Agent / 审查者按 Skill 实际检查，CLI 再对审查记录校验、计分和生成报告。

让每一次上线判断，都有据可查。

先诊断，再整改。不增加产品功能，不混入管理评分。
