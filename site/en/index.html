02 / THE RUBRIC

Nine dimensions. One technical rubric.

No points for owners, approvals, signatures or document counts. Complex architecture is not a quality score.

04 / KNOW THE BOUNDARIES

A review tool. Not a release button.

It does not guarantee finding every vulnerability or turn a high score into release authorization. Your capable agent or reviewer performs the review; the CLI validates records, scores and renders them.

No remote analytics, scripts or fonts in reports or this site. Real reports are ignored by Git; Pages builds only allowlisted synthetic samples. Your agent host has its own data behavior.

Do unknowns count as failures?

No. Unreviewed work is unscored. Partial reviews show known deductions, pending criteria and a provisional upper bound. Critical unknowns prevent a readiness conclusion without pretending that a defect was confirmed.

Is duplicated code always a deduction?

No. Establish shared business semantics and a concrete multi-site maintenance or drift problem. Avoid premature abstraction just to eliminate similar syntax.

Does it support Windows?

The standard-library scripts use portable paths and include py -3 commands and a Windows CI configuration. Actual platform verification is documented separately; configured CI is not a completed run.

Does this automatically scan my project?

Not in this version. An agent or reviewer uses the skill to inspect the real project. The CLI then validates those records, calculates scores and generates the report.
